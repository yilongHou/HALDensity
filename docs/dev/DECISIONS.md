# HALDensity: decisions on hyperparameters, solvers and rules

Status: reference list, 2026-10-24. Each item says what was decided, when, and why; "pending" items are open. Applies to HALDensity v0.2.0 (branch `consolidate`, not yet released) unless stated otherwise. **Update this file in the same commit as any change to a default or rule.** Paths are relative to the repository root unless marked as project notes; project notes live in the HAL-MLE-DE-AOS project repository, not in this package: `notes/haldensity-cv-scoring/`, `notes/hal-free-knot-argument/`, `notes/hal-order-choice/`, `notes/haldensity-restructure/spec_normalizer_knotcap.md`.

## 1. Cross-validation (choosing the L1 bound M)

| Setting | Decision | Why |
| --- | --- | --- |
| Search | Optuna TPE, 50 trials, M log-uniform on [1e-3, 1e6], 5 folds | HALDensity's defaults; confirmed 2026-10-23. 5 folds everywhere decided 2026-10-24: the full-data tuner's former default of 3 now follows the shared `TUNER_DEFAULTS.cv_folds = 5` (discrepancy resolved) |
| **CV score** | **Exact held-out log-likelihood** (`cv_scoring="exact"`, default): exact evaluation at the validation points with the accurate normalizer (§4). `"interpolated"` keeps the old score | The old score interpolated 200 grid values and used a midpoint normalizer; for spiky fits it was inflated by up to 0.1 nats and picked absurd M (e.g. 9.9e5) |
| A trial counts | Only if every fold fit qualifies; if no trial gets a finite score, raise an error (never return an arbitrary M) | A silent all-folds failure returned the first trial's M |
| CV solver | The estimator's own solver defaults with the fallback ladder (§3), **at the default tolerance** (`OptunaHyperparameterTuner(cv_solver_tolerance="default")`) | CV only compares fitted values; tight tolerance in 250 solves costs time for no benefit (decided 2026-10-24) |
| Solver statuses | `optimal_inaccurate` accepted and counted; L1 overshoot recorded, not gated | As in HALDensity |
| Degree k | **Package default: fixed k = 2 for full-data univariate estimation and its targeting** (decided 2026-10-24; `DEFAULT_BASIS_ORDER`); the censored-data and multivariate estimators keep their own default (k = 0, confirmed 2026-10-24); CV over the order on request (`param_overrides={"basis_order": [0, 1, 2]}`, the default before 0.2.0). Experiments: fixed when a study checks the theorem; chosen by CV jointly with M when HAL is compared with other estimators (decided 2026-10-23) | At n = 320 the package's joint CV over {0, 1, 2} was never better than fixed k = 2 (KL of the joint CV relative to fixed k = 2: 0.96, 1.02, 1.16, 1.34 on the jump, slope-kink, curvature-kink and smooth truths), and an order higher than the truth's costs little |
| **Conservative adjustment** | **Off by default at every order** (decided 2026-10-24, by the rule Yilong set in advance for session 69's check); kept as an option (`use_conservative_adjustment=True`, or `"auto"` = k = 0 only) with its margin of **5% of the CV log-likelihood SD**, bisection search | k = 0 with the exact objective (four truths × n = 320 and 1,280 × 50 replicates): the CV-best fit had KL 0.82–0.99 × the adjusted fit's (8 of 16 KL/L2 intervals below 1, none above); the adjustment doubled the smooth truth's boundary bias (0.207 vs 0.123 at x = 0.01); the CVLL imbalance appeared in 0 of 800 fits (largest \|θ\| 1.45). For k ≥ 1 it oversmoothed: L2 worse in 11 of 16 test datasets. Instead, an **internal safeguard at k = 0** (decided 2026-10-24): the final fit warns and asks for a report if adjacent knots < 1e-3 apart carry opposite-sign coefficients both > 10 (flag A) or coefficients > 10 carry > 1/2 of ‖θ‖₁ (flag B); diagnostics recorded in `get_results()["imbalance"]`; not a setting, no refit. The milder pattern (opposite steps ≥ 0.5 within 0.05) is to be tested on the paper rerun's samples first |
| One-SE rule | **Not used** | About 9× wider than the 5% margin; HAL's CV already picks M below the truth's norm |
| CV safeguard for k ≥ 1 | **None** (decided 2026-10-24): the paired-difference rule is not adopted | The k = 1 CV curves decline gently with no pathological fits; a continuous fit cannot hide spikes; plain CV at k = 1–3 beat both sieves in the experiments. Reopen only if the paper rerun's imbalance diagnostics flag a problem. The k = 0 conservative adjustment may also go (session 69's check pending) |

## 2. The fitting objective

| Setting | Decision | Why |
| --- | --- | --- |
| Basis and knots | Truncated powers of order k, knots at the data points (at most K of them, see the knot cap); L1 constraint on all coefficients except the intercept | HALDensity's definition |
| **Knot cap** `max_knots` | **Default `"auto"`: K = 1,000 for k ≥ 1; K = max(1,000, ⌈n^(2/3)⌉) for k = 0** (decided 2026-10-24), at K data quantiles; `None` = every data point. Changes default results only for n > 1,000 | Bounds memory and time at large n and keeps knots at least about 1/K apart. Rough rule for k = 0: a jump can only be placed to within about 1/K, costing about h²/K in squared L2, which must stay below n^(-2/3), so K ≳ n^(2/3) (acts only above n ≈ 31,600); k ≥ 1 needs far fewer knots (about n^(4/15) for k = 1). Benchmark: on a jump density at n = 20,000, K = 1,000 cost 5–13% in L2, K = 250 up to 43%, K = 100 up to 88%; nothing on smooth or kinked densities ([benchmarks/knot_aware_normalizer/](benchmarks/knot_aware_normalizer/README.md)). **Kept after the cap timings (2026-10-24)**: the paper uses the same capped estimator and states the cap as an implementation setting in its appendix (1,000 knots at data quantiles for n > 1,000; max(1,000, n^(2/3)) at k = 0), with no theory remark; `max_knots` stays public (None = every knot). Timings: K = 5,000 would have cost the k = 2 final fit about 100 s at n = 3,200 (1.2 s with 1,000) |
| **Objective normalizer** | **The package's choice, not a user option** (decided 2026-10-24): by order — the exact objective at k = 0, the midpoint rule with the knots added to the grid at k = 1 (both through the step-height rewrite), the old midpoint rule (199 fixed cells, lean data term) at k ≥ 2; d ≥ 2: the multivariate estimator's rule (exact below the cell quota and the Sobol bank above at k = 0, the Sobol bank at k ≥ 1). Chosen per order inside one CV search; `haldensity.core.objective_rules.objective_rule(k, d)` returns the rule and each data-type package implements it; fits record it. Internal hooks for tests, benchmarks and experiment repos: `CVXPYEstimator(_objective_normalizer=...)`, `CVXPYEstimator._knot_aware_formulation` | The old midpoint rule is blind to mass between two close knots: the k = 0 spike (objective log Z 0.19 vs exact 18.4). At k = 2 the knots-added grid cost 107–415 s per 5-fold CV trial at n = 1,280 against 3.4–4.3 s, with about the same CV score. Yilong: "we can tailor different rules for different k, and in future different d"; which rule a fit uses is the package's job, not the user's |

## 3. Solvers and tolerances

| Setting | Decision |
| --- | --- |
| **Final fit at the chosen M** | **One solve: MOSEK at 1e-12** (relative gap, primal and dual feasibility). Fallback ladder with tight tolerances: **CLARABEL 1e-12 → CLARABEL 1e-10 → ECOS 1e-12 → ECOS 1e-10 → SCS 1e-9, the SCS step capped at 600 s** (cap decided 2026-10-24: without it SCS ran past 17 min at n = 20,000). Record solver, status and achieved accuracy (decided 2026-10-24). Code: `CVXPYEstimator(solver_tolerance="tight")` (default; `"default"` = v0.1.0), `haldensity.core.solvers.TIGHT_LADDER`, `haldensity.core.univariate.support.certified_solve` |
| CV trials | Default tolerances (MOSEK first, then the package's waterfall) |
| **Threads** | **Every solver call single-threaded by default** (decided 2026-10-24, so runs on shared servers do not take other people's cores): MOSEK `MSK_IPAR_NUM_THREADS`, CLARABEL `max_threads`, numpy/scipy BLAS pools limited during the call (`threadpoolctl`); `solver_threads` raises it |
| Pruning | Coefficients with \|θ\| ≤ 1e-4 set to zero (HALDensity's rule) |
| **KKT certification** of the final fit | λ = median \|∂L/∂θⱼ\| over kept coefficients with \|θⱼ\| ≥ 0.1·max\|θ\|; **certified** if no kept coefficient has \|∂L/∂θⱼ\| < 0.99λ and no coefficient has \|∂L/∂θⱼ\| > 1.01λ. If ‖θ[1:]‖₁ < (1 − 1e-3)M the bound is not binding and the fit is certified when max \|∂L/∂θⱼ\|/n ≤ 1e-5; at the bound, passing either test certifies (added 2026-10-24). If not certified, try the next solver in the ladder; if none certifies, keep the best attempt from any solver (the fewest coordinates failing the conditions), flagged and warned (decided 2026-10-24). No repair of uncertified solutions: setting small violators to zero and re-checking certified 0 of 18 in the study, and the re-solve-on-the-support variant never certified a problem the ladder could not ([benchmarks/final_fit_repair/](benchmarks/final_fit_repair/README.md)) |
| Point estimate | **The tight, pruned, certified final fit** (point estimates change slightly from v0.1.0; noted in the CHANGELOG) |
| Without MOSEK | The package must work: the free-solver ladder is the full path |

## 4. Normalizing constant (evaluation, reporting, CV scoring)

| Setting | Decision |
| --- | --- |
| Univariate, full data | **Accurate** (default): cell-wise Gauss–Legendre with breakpoints at the knots with nonzero coefficients, 32 nodes per cell, doubled until the change is below 1e-12; exact for k = 0. `normalizer="midpoint"` keeps the old behaviour |
| Multivariate | Exact below a quota; fixed scrambled Sobol bank above it (existing design). In 1-D, Sobol does not beat the midpoint rule ([experiments/sobol-normalizer-1d.md](experiments/sobol-normalizer-1d.md)) |
| **Censored-data estimators** | Keep their own grid normalizers for now. **Pending — part of the RC project handoff** (their targeting relies on grid sums) |
| **Full-data targeting** | **Exact integration** (decided 2026-10-24): cells with edges at the knots and the targeting jumps (targeting points, the initial median), Gauss–Legendre inside, doubled to 1e-12; Newton polishing of the targeting coefficients while the L1 bound is not binding, so the score equations hold to about 1e-12 (Galaxies: 0.012 before at t = 0.0667); `run_m_step` returns the exact TMLE (`estimate`) and plug-in. The median learner stays one step at the initial median |
| **Missed-mass diagnostic** | Every full-data univariate fit records `log_z_gap` (the accurate log Z minus the objective's, nats, at the point estimate) and warns above **0.01 nats**, suggesting `n_grid_points` ≈ 200 / (max x − min x) (decided 2026-10-24; silent inside CV folds, shown on the final fit). Galaxies at k = 2, M = 596,793: 0.064 with 200 points, 0 with 1,000 |
| **Fitting grid `n_grid_points`** | **Public** (decided 2026-10-24): whether the data are too concentrated for the default is the user's call, the one exception to "numerical options are internal"; default 200 unchanged; the tuner passes it to every CV fold and the final fit through `estimator_kwargs`. Galaxies (8% of [0, 1]): 1,000 removes the gap (main peak 80.7 → 65.2, the same at 2,000; a 5-fold CV trial 0.20 → 0.84 s) |

## 5. Variance estimation and inference

| Setting | Decision |
| --- | --- |
| Delta-method SE | On the **certified basis of the final fit** (§3); on by default (`support_refit="auto"`; `None` switches it off). Claim strength: an empirical improvement in the simulations, not a guarantee; the selected basis is not unique (SE/sd 2.4–14 → 0.76–1.3 in the simulations). **If basis cleaning fails** (the final fit does not pass the optimality check): the point estimate is kept but **no SE and no intervals** (NaN), with a warning suggesting a bootstrap or another solver (decided 2026-10-24); `support_refit=None` still gives the original-basis SE on request |
| Inverting the information | **The scaled floor, r0 = 1e-5** (decided 2026-10-24 after SE round 2: "as long as it performs not worse than the fixed rule"): a ridge of 1e-5 times each column's own score variance (the information scaled to unit diagonal, plus 1e-5 I, scaled back), so the SE has no units; the intercept and any column constant on the data are dropped (no spread on the data, e.g. the knot at min(x) at k = 0; review C1, 2026-10-25). The 0.1.0 absolute ridge 1e-6 stays internal (`_inverse="ridge"`) as the reference: the paper's experiments compute both on the same cleaned fits with M chosen by CV, and the condition is re-checked there. Round 2 (180 cells; r0 chosen on training truths, adoption judged on confirmation truths, both rules fixed in advance): on the original data the floor matches the ridge (mean \|coverage − 95%\|, floor minus ridge, −0.026 with bootstrap SE 0.0015); once the data's units are squeezed the ridge loses more than 3 coverage points in 98 of 180 cells while the floor's SE is unchanged to 1e-9; it missed one pre-set criterion only, the pooled median SE/sd on the squeezed copies (1.215 against the ridge's 0.957; per order closer to 1: 1.14 against 0.67 at k = 1, 1.19 against 0.56 at k = 2). Cost: at fixed M on data that fill [0, 1], SEs the same at k = 0 and about 10–20% larger at k ≥ 1; much larger on concentrated data, where the ridge was too narrow (Galaxies, k = 2: band width over the data range 1.61 × the bootstrap's at fixed M, the ridge's 0.43 ×). Round 1's relative cutoff was not adopted (median SE/sd 1.28 against 1.02) |
| Interval scale | **Pending (Yilong, 2026-10-24)**: density scale (default; density +- z SE, lower end cut at 0, the paper's formula) and log scale (`scale="log"`: density * exp(+- z SE / density), same SE) are both computed in the SE study; the test decides which one is claimed. The log scale may help at boundaries and kinks, which round 2's points (the 0.1-0.9 quantiles) do not test |
| Band centre and E[phi] | The rule of the accurate normalizer (Gauss–Legendre with breakpoints at the selected knots; exact for k = 0), so the band's centre is the density `get_density_at_points` reports (decided 2026-10-24; before: a 200-point trapezoid, up to 5.1% off on Galaxies) |
| Pointwise intervals at kinks and boundaries | **Deferred to the paper-version experiment rerun (Yilong, 2026-10-24); report both variants there.** Evidence so far: undersmooth for inference, M ≈ 2× the CV choice (coverage at the k = 1 kink 46–58% → 78–89%; boundary 74–80% → ≥ 93%); CV for the point estimate. Never use the conservative adjustment when the goal is inference |
| Supports | Fixed in advance (e.g. [0, 1]); data rescaled by a known bound, not min–max of the sample. Galaxies: divide by c = 3×10⁵ km/s; raise `n_grid_points` to about 200 / (b − a) if the data occupy a small part [a, b] of [0, 1] (Galaxies: 1,000, Yilong's choice for the case study) |

## 6. Order of the HAL fit (theory and simulations, 2026-10-23)

| Rule | Status |
| --- | --- |
| Default to a moderately high order (k = 2); a higher order than the truth's costs little (for k₀ ≥ 1), a lower one costs more | Theory (project notes `notes/hal-order-choice/note.md`); Lemma A confirmed numerically; Phase B simulation (R = 100 test stage) running |
| If jumps are plausible (k₀ = 0), choose k by CV | Theory; any continuous fit fails in sup norm at a jump |
| Free smearing at the kink happens only when the fitted order equals the truth's and both are 0 or 1 | Theory + simulations (coverage 0.78 at k = 1, 0.94 at k = 2) |

## 7. Package rules

| Rule | Decision |
| --- | --- |
| Scope | Only our methods (HAL) and their implementation; comparison methods and experiments live in experiment repos that pin a tagged release |
| Layout | `core/` (shared by more than one data type; never imports a data-type package; univariate base in `core/univariate/`), `full_uni/`, `full_multi/`, `rc/`, `ic/` (with `ic/current_status/`), `datasets/` |
| Every change | Labelled core or data-type-specific before it is made |
| Targeting | Each data type keeps its own (full data adds basis functions and re-runs the optimization; RC solves an equation for ε); no shared framework |
| RC estimators | All on equal footing in `rc/pipelines.py`: IPCW-HAL, L1MLE at M₁, CVL1MLE (CV over [M₁, 2M₁]), undersmoothed (EIF-mean rule); default CVL1MLE (best in most but not all cases so far) |
| RC: largest observed time | The Kaplan–Meier convention (decided 2026-10-24: "it is our convention as well"): when the largest observed time is censored, it is treated as an event. One helper, `rc.last_time_as_event`. `KaplanMeier.fit` applies it to the data it is fitted on, so the censoring survival estimate stays positive at every observed time; the estimators, the targeting steps and AIPW apply it to their data; the tuners split their folds on the data as observed and apply it to each training fold and the final fit only (review R2, 2026-10-25), so the IPCW weights, the likelihoods and the influence curves count that observation as an event. Held-out losses use the validation data as given. Before, the censoring survival estimate fell to 0 at a censored largest time (about 10% of samples in the tutorials' design), and the influence curves of the mean, RMST, entropy and density L2 blew up |
| RC targeting SE | Every target reports the SE over all observations (decided 2026-10-25). The positivity-filtered SE, which left out the observations near or beyond the point where the censoring-survival estimate fell below the floor (every censored observation when the largest time was censored), is removed with its columns; it was the default of the mean, RMST and entropy, undocumented, and wrong for RMST, whose influence curve never reaches the tail. The floor max(1/(√n log n), clip) on the censoring-survival estimate inside the influence curves stays as a positivity safeguard; `gbar_floor_active` records whether it was active. In the convention check (3,600 replicates) neither triggered with the convention in place. Open for the RC project: the entropy and density-L2 SEs are too small (SE/sd 0.6–0.93, coverage 0.72–0.94, in samples with and without a censored largest time, and with the old code); a diagnostic is planned |
| RC censoring term | The censoring part of every right-censored influence curve integrates E[phi(T*) \| T* > u] against the jump of 1/G, dG(u) / (G(u-) G(u)) (review R1, decided 2026-10-25; it was dG(u) / G(u)^2). One helper, `rc.targeting.eic._censoring_jump_weights`, for the five targets, survival v1/v2 and AIPW; a test checks E[D \| T* = t] = phi(t) - psi under a discrete G |
| AIPW | Kept (Yilong's method); documented as not a plug-in |
| Names | `full_uni` / `full_multi`; `MultvarHAL` unchanged; `MultvarHAL` warns at d = 1 |
| Sample data | `load_galaxies()` returns raw km/s; simple simulators in `datasets/` |
| Warnings | No global warning filters; known noise suppressed locally inside CV folds; CI fails on deprecated calls |
| Precision | Every basis and design matrix in float64 (decided 2026-10-24; float32 before, inherited from the first commit with no recorded reason). A design matrix on its own doubles, but whole fits grow little, since CVXPY holds its own float64 copy: the same peak memory for the right- and interval-censored fits, up to +13% for the multivariate one (d = 2, k = 0, n = 1,000: 2.4 to 2.7 GB); times unchanged. No real memory problem, so no estimator keeps float32 |
| **Public vs internal options** | Numerical choices are the package's job (decided 2026-10-24). Public: `max_knots`, `n_grid_points` (the one exception: data-dependent, the user's call), `solver_threads`, `log_dir` and `log_frequency` (estimator options; a log file only when `log_dir` is given, decided 2026-10-24; the tuner's `log_frequency` is deprecated), `cv_folds`, `metric`, `random_state`, `param_overrides`, `estimator_kwargs`, `use_conservative_adjustment` with its margin settings, `support_refit`, `alpha`, and `tolerance` / `max_iter` of the first-order estimators (plus the statistical `norm_constraint` and `basis_order`). Internal (leading underscore; tests, benchmarks, experiment repos): `_tol`, `_solver`, `_use_secondary_solver`, `_solver_waterfall`, `_normalizer`, `_solver_tolerance`, `_objective_normalizer`, `_knot_aware_formulation`, `_cv_scoring`, `_cv_solver_tolerance`, the conservative search numerics, the SE rule's `_inverse`, `_floor` and `_ridge_param`. 0.1.0 names warn through 0.2.x and go in 0.3.0; options new in the restructure went internal directly |
| Compatibility | Old import paths re-export with a DeprecationWarning through 0.2.x, removed in 0.3.0 (kept light; can be dropped) |
| Removed | `KFold_CV_LambdaSelector`, the comparison module (copied to `HAL_TMLE_RC/from_haldensity/`), multivariate reporting helpers (copied to `multivar-HAL/from_haldensity/`), the MCMC-HAL notebook (conclusion kept in `docs/dev/experiments/`) |
| Versions | v0.1.0 tags the old `main`; branches are deleted only after archive tags on their tips |
